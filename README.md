# agency-metabase infrastructure

Terraform for the AWS resources backing **agency-metabase**. Provisions a
PostgreSQL RDS instance used as a **data source** for a Metabase Cloud
instance (Metabase Cloud manages its own application database, so that is not
provisioned here).

Metabase Cloud connects from outside the VPC, so the database is exposed on a
public endpoint locked down to Metabase Cloud's static IPs via a security
group, with SSL enforced. Additional resources (remote state, a read-only DB
user, etc.) can be added over time.

## Layout

| File | Purpose |
| --- | --- |
| `versions.tf` | Terraform + provider version constraints |
| `providers.tf` | AWS provider config and default tags |
| `variables.tf` | Input variables |
| `main.tf` | RDS instance, DB subnet group, security group |
| `outputs.tf` | Connection details (endpoint, credentials) |
| `terraform.tfvars.example` | Template for your real values |

## Prerequisites

- Terraform >= 1.5 (tested with 1.15)
- AWS credentials with permission to manage RDS/EC2 networking
  (`export AWS_PROFILE=...` or standard env vars)
- An existing VPC with **two or more subnets in different AZs** for the DB

## Usage

```bash
cd agency-metabase-infra
cp terraform.tfvars.example terraform.tfvars   # then edit with your values

terraform init
terraform plan
terraform apply
```

Retrieve the master credentials. By default RDS manages them in Secrets
Manager, so fetch them from there:

```bash
SECRET_ARN=$(terraform output -raw db_master_user_secret_arn)
aws secretsmanager get-secret-value --secret-id "$SECRET_ARN" \
  --query SecretString --output text
```

If you set `manage_master_user_password = false`, the password is generated by
Terraform instead and read with `terraform output -raw db_password`.

## State

Uses **local state** (`terraform.tfstate` in this directory). Because the
generated DB password is stored in state, that file is secret and is
gitignored. To collaborate, migrate to a remote backend later: add a
`backend "s3" {}` block to `versions.tf` and run
`terraform init -migrate-state`.

## Notes & next steps

- The master password is managed by RDS in AWS Secrets Manager by default
  (`manage_master_user_password = true`), so no secret is stored in Terraform
  state. Set it to `false` only if you need Terraform to generate the password
  itself (which then lives in state — treat state as secret).
- `deletion_protection` defaults to `true`. To destroy the instance you must
  first set it to `false` and apply.
- Commit `.terraform.lock.hcl` (the provider lockfile) once generated; it is
  intentionally **not** gitignored.

## Connecting Metabase Cloud

Access is restricted to Metabase Cloud's static IPs (`metabase_cloud_cidrs`,
pre-filled with the **US / us-east-1** addresses from Metabase's
[IP addresses to whitelist](https://www.metabase.com/docs/latest/cloud/ip-addresses-to-whitelist)).
If Metabase changes them or your instance is in another region, update that
variable.

Requirements for this path:

- `publicly_accessible = true` (default) and the DB subnet group must use
  **public subnets** (route table with an internet gateway). Without a public
  route the whitelisted IPs still can't reach the instance.
- SSL is enforced (`rds.force_ssl`), so enable **"Use a secure connection
  (SSL)"** in Metabase's database connection settings.

In Metabase (Admin → Databases → Add database) use the endpoint, port, database
name (`analytics` by default), and the credentials from Secrets Manager above.
For tighter security, create a dedicated read-only Postgres user for Metabase
rather than connecting as the master user.

## Hardening / next steps

- Create a **read-only database user** for Metabase (this Terraform provisions
  only the master user). After apply, connect and run e.g.
  `CREATE ROLE metabase_ro LOGIN PASSWORD '...'; GRANT CONNECT ON DATABASE analytics TO metabase_ro; GRANT USAGE ON SCHEMA public TO metabase_ro; GRANT SELECT ON ALL TABLES IN SCHEMA public TO metabase_ro;`
- Prefer connecting Metabase as that read-only user, not the master.
